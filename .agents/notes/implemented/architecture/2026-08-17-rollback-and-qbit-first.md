# 一键回退 + 所有改动必经 qBittorrent

Status: implemented
Class: architecture

## 背景

要把整个库从英文目录名切换到 TMDB 官方中文名：1298 个文件改名 + 83 个目录改名。
这个量级的改动，**没有回退路径就不该执行**。同时提出一条硬约束：
所有改动必须经由 qBittorrent，绝不在文件系统上单独改而不同步 qBit。

## 决定一：以 run 为单位的事务回退

每次 `apply` 分配一个 `run_id`，每个真正改动了状态的动作在审计日志里附带
**逆操作的完整描述**（`undo` 字段）。`media-agent rollback --run <id>` 按 **LIFO**
顺序逐条还原。

LIFO 是必须的：先改文件名再改目录名，回退就必须先还原目录名，
否则文件的记录路径已经不对了。

各动作的逆操作：

| 动作 | 逆操作 | 记录的关键信息 |
|---|---|---|
| `rename` | 改回原文件名 | 新路径 + 原文件名 + torrent_hash |
| `rename_show_dir` | setLocation 回原路径 + 合并回旧目录 + 还原 AB save_path | 每个种子的**原始 save_path** |
| `recategorize` | 设回原分类 | 原分类名（必须在改之前抓取） |
| `retag` | removeTags | 加过的标签 |
| `trash` | 从隔离区移回 | 隔离区路径 + 原路径 |

还原前逐条核对当前状态与预期一致，不一致就跳过并报告——事后叠加了别的改动时，
宁可少还原，也不要盲目覆盖。

`trash` 若同时删了种子记录，则标记 `torrent_record_lost`：文件能还原，
种子记录还不回来。回退报告会明确说出这一点，而不是假装干净回退了。

## 决定二：改动必经 qBittorrent

- **文件改名**：有种子关联的一律走 `torrents/renameFile`。种子文件列表里找不到
  对应条目时**报失败并中止**，绝不退化成文件系统改名。只有确认无种子关联的
  纯本地文件才允许 `Path.rename`，且在审计里记 `via: filesystem` 以便区分。
- **目录改名**：由 `setLocation` 让 qBittorrent 自己搬运，而不是 `Path.rename` 整个目录。
  裸 mv 会让目录下所有种子的记录路径瞬间失效——库里现存的 28 个死链种子
  正是早先这么干留下的。任一种子 setLocation 失败即中止整个目录改名，
  避免留下半迁移状态。

实测效果：1312 项改动执行完毕，**死链种子数 28 → 28，零新增**；
362 个种子全部保持 `stalledUP` 做种状态。

15 个 NUKITASHI 文件改名失败，原因正是"种子里找不到该文件"——
这是约束在正确地起作用，而不是缺陷。

## 踩到的 bug：递归合并

目录改名后需要把无种子关联的残留文件搬到新目录。初版只遍历顶层：

```python
for item in old.iterdir():
    dest = new / item.name
    if dest.exists(): continue      # ← 这里
    shutil.move(item, dest)
```

当新旧目录下都有 `Season 1` 时，`dest.exists()` 成立 → 整个子目录被跳过 →
里面的文件全部滞留旧目录。结果是 **19 个目录新旧并存、50 个文件掉队**。

改为递归逐**文件**移动并保持相对结构，macOS 的 `._*`/`.DS_Store` 元数据垃圾
直接丢弃（它们还会让 `rmdir` 失败，造成"旧目录删不掉"的假象）。
同名文件不覆盖，计入 `stranded` 交给去重规则处理。

新增 `media-agent repair --run <id>` 修复已经产生的分裂状态：
按审计记录找出 old/new 配对，活种子走 setLocation、失联种子走文件系统合并。
19 对全部合并完成，复查 0 残留。

## 放弃的替代方案

- **改动前整库快照**：媒体库 1.3TB，代价不现实。事务日志才是可行的粒度。
- **回退时重新推导原状态**：推导不出来——TMDB 标题会变、规则会演进。
  必须在改动**当时**把原值记下来。
- **目录改名用 `Path.rename` 后再 setLocation 补记录**：两步之间 qBit 指向不存在的
  路径，中途失败就是半损坏状态。让 qBit 主导搬运没有这个窗口。

## 风险与缓解

**dry-run 的回退预演会大量报"目标已存在"。**
因为预演不真的还原目录名，后续文件的还原路径校验就对不上。这是预演固有的局限，
不代表真实回退会失败。真实回退按 LIFO 先还原目录，路径随即恢复有效。

**隔离区过期后 `trash` 不可回退。**
保留期 30 天，过期文件真删，此后 `restore_from_trash` 会明确报"隔离区文件已不存在"。
