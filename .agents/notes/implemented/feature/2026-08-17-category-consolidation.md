# 分类合并：一部番一个分类，名字取 official_title

Status: implemented
Class: feature
Rule: `category-consolidation`, `stale-torrent-path`

## 现象

qBittorrent 里 55 个分类、362 个种子，其中 **8 个 show 目录被拆成了 2-3 个分类**：

```
Gnosia                 → [古诺希亚] 3 个 + [古诺西亚] 18 个
黄泉使者               → [黄泉使者] 14 个 + [黄泉的使者] 5 个
入间同学入魔了         → [入间同学入魔了] 14 个 + [入间同学入魔了！] 4 个
攻壳机动队 ...         → [攻壳机动队] 4 个 + [攻壳机动队 THE GHOST IN THE SHELL] 1 个
无职转生 ～...～       → 带空格版 2 个 + 不带空格版 5 个
恶女不才，请多关照 ... → [Bangumi] 1 个 + 两种译名各若干
```

成因是每次换来源订阅、或按不同译名建分类，就多出一个碎片；老的碎片没人清理。

原有的 `wrong-category` 规则治不了这个，因为它有一个宽容分支：
「分类名等于目录名就放过」。而 `黄泉使者` 恰好等于目录名，于是它永远不会被
修正到 TMDB 的官方标题 `黄泉的使者`——**这个宽容分支正是碎片长期存活的原因**。

## 决定

用 `category-consolidation` 取代 `wrong-category`：

1. **归属判定用磁盘目录，不用分类名。** 落在同一个 show 目录下的种子必然是同一部番，
   这是唯一可靠的分组依据；分类名本身正是待修正的对象，不能拿它当依据。
2. **规范名 = `official_title`**（TMDB 本地化标题 > AutoBangumi official_title > 目录名）。
   删掉"等于目录名就放过"的宽容分支。
3. **合并后变空的分类一并删除**，避免下拉框里堆满死分类。
   删除前会重新核对该分类确实已无种子——合并动作可能在本轮早些时候失败。

### 路径前缀兜底

首轮跑完后 `Gnosia` 仍然分裂。查下来是那 18 个种子的 `content_path` 指向
`GNOSIA - S01E01 [WebRip...].mkv`，而磁盘上文件早已被改名为 `Gnosia S01E01.mkv`
——**路径成了死链**，磁盘扫描关联不上这些种子，分组时它们根本不在候选里。

所以分组时增加一层兜底：content_path 以该 show 目录为前缀的种子，
即使文件已不存在也算作属于这个目录。不兜这一层，这类种子会永远合并不掉。

### 顺带产出：`stale-torrent-path`

死链本身是个独立问题，值得单独一条规则报出来。实测 28 个：
Gnosia 18 个、Re Zero 10 个——**都是当初用文件系统 `mv` 改名造成的**，
正是本项目 AGENTS.md 第 3 条禁止的操作（有种子的文件改名必须走 qBittorrent API）。

这条规则**只报不改**：重新定位需要确认新旧文件的对应关系，
盲目 setLocation 可能把种子指到错误的文件上，不是能闭眼自动做的事。

## 结果

```
碎片目录   8 → 0
相似异名   4 组 → 0
空分类     21 → 0
分类总数   55 → 42
```

## 放弃的替代方案

- **按分类名相似度合并**（编辑距离/子串）：会把 `想要成为影之实力者` 和
  `想要成为影之实力者！` 合对，但也可能把两部真的不同的番合错。
  磁盘目录是确定性的证据，相似度是猜测。
- **保留"等于目录名就放过"**：正是它让碎片活了下来。
- **给 `stale-torrent-path` 配自动 setLocation**：需要在新旧文件间建立对应关系，
  而这恰恰是丢失的信息。宁可报出来让人处理。

## 风险与缓解

**official_title 取 TMDB 后，分类名可能变得很长。**
实测 `My Ribdiculous Reincarnation` → `女神"异世界转生想成为什么"我"勇者的肋骨"`。
这是"统一到官方名"的既定代价；不接受的话应该改 `Show.official_title` 的优先级，
而不是在合并规则里开特例。

**分类名与目录名可能不一致。**
TMDB 中文标题会让 83 个英文目录名与分类名分叉。两者收敛需要同时应用
`title-drift`（改目录名），那是量级大得多的操作（动刮削、做种路径、
AutoBangumi save_path），故意留作独立决策，不在本规则的作用范围内。
