# 隔离区安全清理池

## 为什么不能按时间清

隔离区是本项目里删除的唯一形态：`trash` 把文件移进去并记下逆操作，
`trash_retention_days = 30`。但"到期就无差别清空"是危险的——万一当初判重判错，
或者留下的那份其实是个截断的空壳，隔离区就是最后一份原件。

54 GB 里没有一份超过 30 天，可它已经占满了盘的一角。需要的不是等，
是一个**可验证的安全判据**。

## 判据

一份隔离文件进入待删池，必须同时满足：

1. **库里有替代者。** 从它当初的路径推出集位（剧集 / 季 / 集号），
   看库里现在有没有文件占着这个集位。查的是**当前实际状态**，
   不是审计日志里记的"保留了谁"——日志是历史，文件可能后来又被换过。

2. **替代者是完整的。** 必须有对应种子，磁盘大小**恰好等于**
   `torrents/files` 声明的大小，且种子进度 100%。

第二条是关键。光有文件占位不够：一个下了一半的文件同样占着集位，
拿它当"库里已经有了"的证据，就会把唯一完整的那份删掉。

## 天然进不了池的

- `extras-in-library` 清掉的特典/PV（120 份）：它们被清理正是因为 TMDB 没有
  对应条目，按定义不存在"库内替代者"。去留是另一种判断。
- 没有审计记录的（49 份）：早期手工整理留下的 `manual-*` / `dupe-*` 目录，
  无从得知当初代表哪一集。
- 替代者是无种子的孤儿文件（28 份）：验证不了大小。

## 一个自己造的误报，当场修掉

第一版把"集位"定义成"原路径的父目录"。于是两份原本就躺在库内 `.other/`
隔离子目录里的文件（《义妹生活》S01E07、《药屋少女的呢喃》S01E24）
被判成"库里 S01E07 现在是空的——这份可能是唯一的原件"——
而它们的正片明明都在 `Season 1/` 下。

改成在**整部番的各季目录**里找集位（跳过 `.` 开头的库内隔离目录）。
这也顺带覆盖了"整部番按 TMDB 重编排过"的情况（药屋的 Season 2 并进了 Season 1）。

**误报比漏报更伤**：一道安全检查一旦开始喊狼来了，就没人再信它，
最后连真的警报也一起被忽略。

## 用法

```
media-agent purge              # 预演，列出待删池
media-agent purge --verbose    # 连保留原因一起看
media-agent purge --apply      # 执行
```

默认只预演。执行前另做过一次独立复核（不复用 purge 自己的判定，
直接从 qBittorrent 和磁盘对账），28 份全部一致。

首次运行：225 份 / 54.2 GB → 删 28 份 / 16.6 GB，剩 197 份 / 38 GB。

## 没有接进自动轮次

判据虽然可验证，但删除不可逆，而 `run` 是全自动的。
先作为手动命令用一段时间，观察它每次挑出来的东西是否都合理，再决定要不要自动化。
