# 一次全库清理，挖出五个「不报错、只是不干活」的 bug

Status: implemented
Class: bug-fix
Rule: `extras-in-library`、`episode-available`、`title-drift`、`unrenamed-file`、扫描层

起因是「处理全部问题」——库里报 154 条。清完发现其中 142 条不是问题，
而剩下的 12 条背后藏着五个**从不报错的 bug**。它们的共同形态是：

> 代码在跑、日志正常、每一步都"成功"，只是不再做它该做的事。

## 一、`\bIN\d*\b` + IGNORECASE 吃掉了整部《攻壳机动队》

特典标记表里有 `r"\bIN\d*\b"`（匹配 `IN01` 这类蓝光特典编号）。
`\d*` 允许零个数字，再叠上 `re.IGNORECASE`，它就匹配英文介词 **in**。

《The Ghost **in** the Shell》每下一集就被 `extras-in-library` 判成特典、
trash 进隔离区，**而日志显示的是一次成功的"清理特典"**。
翻审计日志：8/18 删了 E01–E05，8/19 删了 E06，8/30 删了 E07 和刚抓的 E08。
连带误删《Skeletons **in** the Closet》《倾城之恋 Love **in** a Fallen City》两部电影。

之前那句"攻壳机动队 6 个孤儿种子 → 0"其实是同一个 bug 的另一面：
文件被删、种子成孤儿，我修了孤儿，没问下一个问题——**它们当初为什么会没了**。

修法：两个字母的缩写（IN/PV/CM/SP）一律要求 `\d+`，或者要求独占方括号
（`[SP]` `[CM]` 是标记，正文里的 in/cm/sp 不是）。
14 个正片从隔离区捞了回来（30 天保留期救了这一次）。

**教训**：正则的宽松量词（`\d*` `?` `*`）叠上 IGNORECASE，等于给自己埋雷。
两个字母的缩写在自然语言里几乎一定有同形词。

## 二、`Finding.key()` 让抓取器每轮只补得了一集

```python
return (self.kind, self.path or self.torrent_hash)
```

抓取器报的"S04E20 可抓取"说的是**磁盘上还不存在的一集**——既没有 path
也没有 torrent_hash。于是全库每一条待抓记录都得到同一个键
`("episode_grabbable", "")`，`run_all` 认为它们是同一个问题，
除第一条外全部丢弃，**不留任何日志**。

外在表现完美：每次 diagnose 报一条待抓、apply 成功、下次再报一条。
修好之后同一个库立刻报出 5 条待抓、9 部番缺集——之前"只剩 2 个问题"是假象。

**教训**：去重键退化成常量时，去重就变成了丢弃。凡是"或"出来的兜底键，
都要问一句：所有分支都为空时会怎样。

## 三、缓存加字段不换 key，日期校验静默失效

上一轮刚给 feed 条目加了 `pub` 字段做跨季校验。缓存 key 没变，
于是旧缓存里的条目全都没有 `pub`，`_plausible_for` 一律返回"无日期"——
按设计"无日期不淘汰"，整道闸**退化成不设防**。

后果：抓了一集 2023 年的《入间同学入魔了！第3季》第 20 集进 Season 4。
和上次那个错配一模一样，而校验代码就在那儿运行着。

修法：缓存 key 带结构版本（`mikanfeed:v2:{id}`），改字段就 +1。

**教训**：给缓存数据加字段 = 悄悄制造了两种格式。新代码读到旧格式时
不会报错，只会得到"字段缺失"，而缺失往往被设计成宽容分支。

## 四、路径前缀用 startswith，把三个目录名叠成一团

```python
if (t.get("save_path") or "").startswith(str(old))    # 少了 "/"
```

`/Media/青春猪头` 于是"包含"了 `/Media/青春猪头少年不会梦到兔女郎学姐`——
两个毫不相干的兄弟目录。改名时把兄弟目录的种子也圈进来，
`sp.replace(old, new, 1)` 换掉前缀，每跑一轮尾部就多接一段：

```
青春猪头少年不会梦到兔女郎学姐
青春猪头少年不会梦到兔女郎学姐少年不会梦到兔女郎学姐
青春猪头少年不会梦到兔女郎学姐少年不会梦到兔女郎学姐少年不会梦到兔女郎学姐
```

叠了三层才被发现，因为**每一轮的操作本身都成功了**。

同样的写法在 `actions.py` 两处、`scan.py` 一处。抽成 `under()` / `repath()`
统一修掉。有意思的是：我排查时写的勘察脚本也用了 `startswith`，
于是先得出"三个目录各有一个种子"的错误结论——**同一个 bug 骗了我两次**。

## 五、规则拿剧集的尺子量电影和已归置的特典

154 条里 142 条属于这一类：

| 噪音源 | 条数 | 为什么不是问题 |
|---|---|---|
| 45 部电影 | ~45 | 电影没有集号，"无法解析集号"是必然而非异常 |
| `.shorts`/`.extras`/`.other` 里的文件 | ~69 | 以 `.` 开头，刮削器不扫描——**放进去就等于处理完了** |
| 物语系列 14 个目录 | 5 | TMDB 把多部独立作品收成一个条目，合并会毁掉分卷组织 |
| 演进器的"规则盲区" | 43 簇 | 全是电影，演进器在为一个不存在的问题立规则 |

前两类靠扫描层分流解决（`is_movie` / `extras_files`）。第三类要区分
"同一批内容存了两份"（银八老师繁简两个目录，各 12 集）和
"不同作品共用一个 TMDB 条目"（化物语/倾物语/囮物语…）——
判据不能用交集、也不能用子集（倾物语 S01E01–04 **正好是** 化物语
S01E01–15 的子集，第一版就这么错了），要用**重合比例**。

清完之后 154 → 12，且剩下的 8 条是"这集正在下载中"。

## 附：我自己在修复过程中造成的一次事故

写恢复脚本时用了 `Path(u.get("trash_path") or "")`。字段为空时
`Path("")` 得到 **`Path(".")`**——当前工作目录。它 truthy、也 `exists()`，
顺利通过了我写的两道检查，然后 `shutil.move(".", dst)` 跨设备退化成
copytree + rmtree，把整个 `~/media-agent` 搬进媒体库再删掉。

数据没丢（copytree 先于 rmtree，内容原样躺在目标路径下），搬回来即可。
但这条值得记：

- **空字符串转成 Path 是 `.`，不是"无效路径"。** 空值要在转 Path 之前拦。
- **`shutil.move` 对目录会 copytree+rmtree。** 只想搬文件就先 `is_file()` 断言。
- 恢复类脚本用 `copy2` + `unlink`，**永不 rmtree**——先确认落地再删源。
