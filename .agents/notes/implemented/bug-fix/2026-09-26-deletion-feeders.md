# 喂给删除的检测器错误（整改第 2 阶段，逐节追加）

**日期**: 2026-09-26
**状态**: implemented / bug-fix
**触发**: 整改第 2 阶段要在执行器里加一道统一的删除关口，而关口只能拦住
"执行那一刻看得出来的"错误；检测器把集号算错、把正片当特典、把合集整个判输，关口看到的
就是一条参数自洽的删除。这份笔记记录喂给删除的几处检测器错误，按提交逐节追加。

## 1. AutoBangumi 的 `episode_offset` 只换算发布名，不叠加到已规范的名字上

**现场**：生产 AB 订阅 id 37，《超超超超超喜欢你的100个女朋友》第三季按绝对集号 25–36 发布，
`episode_offset=-24`。AB 把 `- 25` 换算成第 1 集、改名成 `… S03E01.mkv`。

**错在哪**：`builtin._resolve` 对**每个**没钉 `ma:` 的文件都加这个偏移（`_apply_offset`）。
已经是 `S03E01` 的规范名再减 24，落进 `(3, -23)`；刚下完、还叫 `- 25` 的新版本落进 `(3, 1)`。
后果：

- 同一集的两个文件永远不在同一个判重桶里，重复看不见；
- 新版本的改名撞上「集位被占」，每轮一条跳过；
- `kernel.episode_of_file`（`have` / 抓取 / 订阅健康的集号来源）完全不看偏移，把 `- 25` 算成
  第 25 集——同一个文件在两条链路上是两个答案；
- 原始集号本来就是季内编号时（`S3 - 01`）减出负数，改名规则会提议 `S03E-23`。

**修法**：`naming.apply_episode_offset(raw, ep, offset)`——名字里有显式 `SxxEyy` 就原样返回
（那是换算之后的结果），否则加偏移；结果不是正数返回 None（认不出，交给人）。`_resolve`
与 `episode_of_file(…, episode_offset=)` 共用它；`have_episodes` 从订阅行取偏移传进去。
`Sxx - yy` 这种带季号但不是 `SxxEyy` 的发布名照旧换算（AB 对整条订阅的原始集号都加偏移）。

**影响面**：整改前的只读核实——生产只有 AB id 37 这一条订阅的偏移非 0。`grab._inflight` 只认规范名
（`allow_release_name=False`），不受影响；`subscription._disk_episodes` 对这部番的发布名
从此按季内集号计。

**测试**：`tests/test_episode_offset.py`——规范名与发布名落进同一个桶、判重看得见这对重复；
`episode_of_file` / `have_episodes` 与判重同一口径；换算出负数的是 `unparsable`、不提议改名；
对照组：发布名照旧换算。改前 4 条红、对照组绿。

## 2. 判重输家：一律 `file_only`，并点名保留方与集位

**以前**：普通输家的动作只有 `{path, torrent_hash}`，没有 `file_only`；合并发布的兄弟才有。执行器于是
对普通输家整种子作废——输家若在多文件合集里，其余十几集跟着失去做种，`torrent_record_lost` 而且没有
magnet，回退加不回来。生产审计 63 条 duplicate-episode 的整种子作废（当时没记文件数），例：3年Z组银八
老师 [01-12]（12 个文件）与另一个种子共用 `Season 1`，任何一个单集种子赢了它的某一集，整个合集就被摘。
保留方从不进动作参数：`_op_trash` 看不到它，`content_digest` 只写进 evidence、从不把关。

**现在**：
- 有种子的输家一律 `file_only: true`。种子此刻只有这一个要下载的文件时，执行器（删除关口 I3）自己
  退回整种子作废——所以单集种子的行为不变。关口的 I3 也会把没标 `file_only` 的请求自动降级；检测器
  这边先把话说对。
- 输家与合并发布的兄弟都带上 `slot: [季, 集]`（解析过偏移与钉子的那个）、`keep_path`、`keep_hash`、
  `keep_size`（诊断时的大小：有种子的是声明大小，纯本地的是盘上大小）、`keep_digest`（大小 + 头尾 8MB
  的内容摘要）。关口据此在执行那一刻复核保留方（I1）与同种子兄弟的封存例外（I4）；审计的
  `deletion.keeper` / `deletion.slot` 也从这里来，purge 以后不必再从文件名或 summary 反推集位。

**测试**：`tests/test_duplicate_feeders.py`——合集里输掉的一集：动作是 `file_only`、点名了保留方
（路径 / 种子 / 大小 / 摘要）与集位；端到端：合集照常做种、只有那一集被设为不下载并进隔离区，
审计记着保留方与集位，赢家同批拿到集位名；合并发布的兄弟点名同种子的保留方。改前 3 条红。

## 3. 封存：两个种子都封存时交给人；探测不可用时不失封

**两个种子都封存着同一集**：停滞超过 `DEAD_TORRENT_HOURS` 的种子，抓取放行换源；或者手动加了一个
同钉子的种子。两个不同的种子都钉着 `ma:S01E08`、都复核通过——以前检测器只封存偏好分最高的那个，
其余当输家删掉。两个都是择源的结论（字幕组、版本），删哪个不该由检测器按偏好分随手定。
现在报 `seal_conflict`（classified、没有动作，`evidence.torrents` 列出各个种子），封存候选一个都不删；
偏好分最高的那个仍当保留方，没钉 `ma:` 的第三份照常判输。

**封存不稳定**：`probe` 超时 / 出错返回 None（进程内缓存这个 None），`meets_requirements` 退回只看名字；
LoliHouse 的内部名只写 `ASSx2`，过不了"中文字幕"硬门槛（`tests/test_seal_slot.py` 第 3 组）。昨天探到
两条中文轨封存了的，今天 ffprobe 一超时就失封，排名又可能输给别的版本，被当输家删掉。现在钉着 `ma:`、
复核没过、**而探测不可用**的，报 `seal_unknown`，本轮既不删它、也不拿它当保留方；探得到而且确实不合格的
（零中文轨的生肉）照旧 `seal_failed`、交回画质规则。复核靠名字通过（探测不可用但名字写着简繁内封）的
仍按封存处理——与以前一致。

删除关口的 I4 在执行那一刻独立兜底（`architecture/2026-09-26-deletion-gate.md` 第 3 节）；检测器这边
改的是"不产出注定被拒的删除、把该人看的报出来"，否则每轮都会多一条「删除关口：I4」的跳过记录。

**测试**：`tests/test_duplicate_feeders.py`——两个种子都封存：没有删除动作、报 `seal_conflict`；再加一份
没钉的：只删它、保留方是两份封存之一；整轮收敛后两份封存都在、隔离区是空的；探测不可用的钉子不当输家、
报 `seal_unknown`。改前 3 条红（整轮那条靠关口 I4 已经是绿的）。

## 4. 特典规则只看标题之后的部分；不碰钉着的正片、不碰某集唯一的文件

**潜伏的现场**：`ExtrasDetector` 把 `is_extra` 用在整个文件名上，而规范名是 `{TMDB 标题} SxxEyy.ext`。
标题里带 `trailer` / `preview` / `menu` / `PV` / `特典` / `菜单` / `creditless` 的番，**每一集**都会被当成
特典、`file_only` 移进隔离区——封存的、钉着 `ma:` 的也不例外。与"The Ghost **in** the Shell 整部被判成
特典"（`naming.EXTRA_MARKERS` 的注释）同一类，那次只修了 `IN` 一个记号。整改前核实：生产上 0 个标题、
0 个规范名命中，所以是潜伏的。删除关口对"特典处置、没钉 `ma:`"的文件放行（特典名字里碰巧认得出集号
不该挡住清理），挡不住这一类——所以要在检测器这里修。

**现在**：
- `naming.is_extra_of(filename, titles)`：先把作品标题（规范标题、目录名、TMDB 标题、AB 的
  official_title / title_raw）**按词边界**从名字里拿掉（标题 `K` 不能拿掉 `mkv` 里的 k），再看剩下的
  部分有没有特典记号。`builtin._is_extra(f, show)` 是所有内置检测器共用的判据：改名、判重、改名撞车
  以前也用整名判断，标题带记号的番整部不改名、不判重——特典规则认定不是特典的，它们也当正片。
- 钉着 `ma:` 的**正片**不当特典：种子里唯一的视频，或名字认得出钉着的集号。它是抓取器认定的那一集，
  归判重管（而且可能封存着）。钉着的合集里的 NCOP 不是那一集，照旧清理。
- 某集**唯一**的可播文件不当特典：名字认得出集号（`_resolve`，含钉子与偏移），而同一集没有别的下完了的
  正片。标题记号藏在认不出的罗马音标题里（发布名 `[G] Trailer Park Boys - 05`、没有 AB 订阅可以认出
  标题）时靠这一条——宁可留着一个真特典，也不删掉唯一的一集。

**测试**：`tests/test_extras_title.py`——标题带「菜单」的番三集规范名都不当特典、整轮收敛后一个不少；
标题之后的 NCOP 照旧是特典（对照）；发布名的罗马音标题带 Trailer、它是第 5 集唯一的文件，不当特典；
钉着 `ma:S01E05` 的正片另有一份也不当特典；钉着的合集里的 NCOP 照旧（对照）。改前 5 条红。

## 5. 死种自己的 `.!qB` 半成品经关口移进隔离区

**第 1 阶段留下的**：死种处置收窄成"只摘记录、磁盘一个字节都不动"（以前 `content_path` 是整个 Season
目录）。生产上 3 次死种处置本来就都是 `freed 0`——半成品留在盘上。代价：

- 占空间：隔离区与媒体在同一个约 94% 满的 APFS 容器里（critic N8），而半成品与完整文件一样大；
- **占着集位名**：停滞换源时（抓取放行新源，op 0；同批摘旧种子，op 1），新种子下完也改不过去——
  占用闸门看到盘上别人的 `X.!qB`，按设计拦下（改过去就是接着往那份半成品里写；grab 调研 S1）。
  `test_grab_stale_bypass.py` 用一条 `xfail(strict=True)` 记着它。

**现在**：`DeadTorrentDetector` 在给出 `drop_torrent` 的同时（有已下完成员、只报告的那种不算），为
死种**自己的**、没下完、优先级非 0 的条目在盘上的 `X.!qB` 各出一条 `trash`（kind `dead_partial`，
Finding 按路径去重，互不吞并）。执行顺序：摘记录（op 1）→ 隔离（op 5）。删除关口对处置类别
`dead_partial` 另加两条：

- 只许动 `.!qB`——参数被写成了正片的路径也拒绝；
- 那个死种此刻必须已经不在 qBittorrent 里（同一批里被摘掉了，或诊断后被人删了）；摘除被跳过
  （又有了做种、有成员下完了、关口拒绝）→ 半成品不动。

再加上通用的 I2：另一个种子仍声明着 `X`（改到同一个集位名上、正往里写的新种子）→ 不动。
半成品不是可播文件，I1 / I4 不适用。进隔离区、`restore_from_trash` 可回退；回退时先搬回半成品、
再凭 magnet 把种子加回来（LIFO）。

**测试**：`tests/test_dead_partials.py`——单文件死种：摘记录 + 半成品进隔离区（`deletion.disposition`
为 `dead_partial`）；NoSubfolder 死种与健康邻居共用 Season 目录：只有它自己的两份半成品离开；别的
种子仍声明着同名文件：摘记录照做、半成品不动（「删除关口：I2」）；诊断后又有了做种：摘除跳过、半成品
不动；有已下完成员的死种什么都不动；`dead_partial` 处置拿到正片路径被拒；回退把半成品搬回、种子加回。
改前 6 条红。`test_grab_stale_bypass.py` 的 xfail 转绿、去掉标记，同文件"真停滞"那条改为断言半成品
进了隔离区。`test_dead_torrent.py` 里"磁盘一个字节都不动"的断言改成"只有死种自己的半成品离开"，
回退计数加上半成品；`test_rollback_claims.py` 的三条重加用例只执行摘记录那一步（它们测的是重加）。

## 6. 特典的"某集唯一的文件"只数真能播的，合集在下时同集的正片也算

2026-09-26 审查对第 4 节兜底的两处复核（改前两条都复现）：

- **幻影把兜底打穿**（数据丢失向）：`_only_copy` 数"同一集另一份下完了的正片"时只看 `is_incomplete`，
  不看它在不在盘上。一个种子说下完了、盘上却没有的幻影（LAT-01；用户经 Jellyfin 删文件也会造出来）
  就算"另一份"，唯一真实的 `[G] Trailer Park Boys - 05` 被当特典隔离；关口对没钉子的特典不问集位，
  `run` 30 天后按特典到期硬删——这一集就没了。生产上目前没有带记号的标题，所以是潜伏的，但它正是兜底
  要防的形态。
- **合集还在下时带集号的特典照下不误**（第 2 阶段的回归）：BD 合集的特典常带集号（药屋
  `Kusuriya no Hitorigoto[menu][S01E03]` / `[PV][S01E01]`，吊带袜 `[menu][01]` / `[PV][05]`，K-ON Moozzi2
  `Menu - 01..09`；生产隔离区的 `orphanqb-20260830T133705/PV/…!qB` 说明它们确实是在合集里下的）。合集在下
  时那一集的正片就是合集自己的成员，也没下完——只数下完了的，特典就成了"唯一的一份"，不提处置，占着带宽
  与 94% 满的容器下完（main 上立刻设为不下载，`tests/test_extras_in_progress.py` 的本意）。

**现在**（`ExtrasDetector._only_copy`）：
- 另一份要**真能播**（`builtin._playable`）：不是幻影、盘上是普通文件、不是 0 字节、有种子的不比声明的小；
- 特典自己还没下完时，同一集**也还在下**的正片同样算数——设为不下载可回退、一个字节都不动；正片自己
  没下完时这份是不是它不急这一轮。特典已下完、同集正片还在下的，仍按"唯一"留着，等正片下完下一轮再处置。

**测试**：`tests/test_extras_title.py`——另一份是幻影 / 0 字节 / 截断时，发布名带记号的第 5 集不当特典；
整轮跑下来它还在库里（审查的现场）。`tests/test_extras_in_progress.py`——药屋合集 50% 时 `[menu][S01E03]`
与 `[PV][S01E01]` 立刻设为不下载；对照：发布名带记号、同集没有别的正片的在下合集成员照常下载。改前 5 条红。
关口与隔离区处置那两层见 `architecture/2026-09-26-deletion-gate.md` 与 `…-quarantine-disposal.md` 的后续小节。
